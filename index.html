Webhook Drift Scenarios (Trigger During Demo)

AUTO-FIX LOW RISK

Field Rename: receipt → receipt_id

Razorpay renames a field in the order.paid webhook payload. Structural change, semantic equivalent. Rebase generates adapter automatically.

BLOCKED CRITICAL

Semantic Shift: status: "captured" meaning change

In payment.captured webhook, "captured" now means "held for review" instead of "payment complete". Schema identical, semantics dangerous. Rebase blocks auto-fix.

AUTO-FIX MODERATE

Event Rename: payment.captured → payment.completed

Razorpay changes the event name. Your webhook handler stops matching. Rebase detects the event type drift and maps the new event name to your existing handler.

Razorpay Webhook Setup

1
Create Razorpay Account

Go to https://dashboard.razorpay.com/signup and sign up. No business docs needed for test mode.

2
Get Test API Keys

Dashboard → Settings → API Keys → Generate Test Key. You'll get key_id (starts with rzp_test_) and key_secret.

3
Expose Localhost with ngrok

Razorpay needs a public URL to send webhooks. Run:
npx ngrok http 3000
Copy the https://xxxx.ngrok-free.app URL.

4
Configure Webhook in Razorpay

Dashboard → Settings → Webhooks → Add New Webhook.
Webhook URL: https://xxxx.ngrok-free.app/webhooks/razorpay
Secret: Create a webhook secret (save it in .env as RAZORPAY_WEBHOOK_SECRET)
Events: Select payment.captured, order.paid, payment.failed, refund.processed

5
Add Keys to .env 
RAZORPAY_KEY_ID=rzp_test_xxxxxxxxxxxx
RAZORPAY_KEY_SECRET=your_key_secret
RAZORPAY_WEBHOOK_SECRET=your_webhook_secret
6
Trigger a Test Payment

Use Razorpay's test card 4111 1111 1111 1111 (any future expiry, any CVV) or UPI test ID success@razorpay. After payment, Razorpay will POST the payment.captured webhook to your endpoint. Rebase will observe the payload and capture baseline.
